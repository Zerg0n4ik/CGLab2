# Лабораторная работа №2 — продолжение лабораторной №1

Проект построен **на структуре первой лабораторной**. Основная фигура остаётся додекаэдром. Сохраняются прежняя организация проекта и четыре основных этапа приложения: `initialize()`, `shutdown()`, `update()` и `render()`.

## Что осталось от лабораторной №1

- Додекаэдр с той же таблицей вершин и пятиугольных граней.
- Расчёт матриц преобразования и отрисовка объекта через существующий Vulkan-пайплайн.
- Управление положением, вращением, масштабом и цветом объекта.
- Анимация, её скорость, радиус орбиты и высота движения.
- Переключение между перспективной и ортографической проекцией.
- Сохранены `main.cpp`, `math.hpp` и интерфейс `application.hpp` первой лабораторной, кроме изменения заголовка окна.

## Что добавлено во второй лабораторной

- Камера с редактируемыми координатами, yaw, pitch и FOV.
- Освещение Blinn–Phong: окружающее, направленное, точечное и прожекторное.
- Настройки цвета материала, зеркальной составляющей и shininess.
- Добавление и удаление точечных источников и прожекторов в панели ImGui.
- Затухание точечных источников и прожекторов пропорционально `1 / distance²`.
- Плавный край светового конуса между внутренним и внешним углами.
- Цветные сферические маркеры источников и линии конусов прожекторов. Вспомогательная геометрия добавлена в те же вершинный и индексный буферы после геометрии додекаэдра.

## Организация кода

Структура каталогов не менялась по сравнению со стартовым проектом:

- `source/main.cpp` — создание окна и главный цикл приложения. Основа первой лабораторной сохранена.
- `source/application.cpp` — состояние объекта, камера, элементы ImGui, обновление матриц и отрисовка. Контролы первой лабораторной находятся в разделе `Object (Laboratory 1)`.
- `source/application.hpp` — исходный интерфейс приложения.
- `source/graphics_internal.hpp` — структуры Vulkan-буферов, uniform-данных и контекст рендеринга. Добавлены только данные, необходимые для света и маркеров.
- `source/graphics_internal.cpp` — существующая инициализация Vulkan. Внутри неё расширены формат вершины (добавлена нормаль), геометрические данные, дескрипторы и буферы для света.
- `source/math.hpp` — математические функции первой лабораторной без переписывания.
- `shaders/shader.vert` и `shaders/shader.frag` — нормали и модель освещения Blinn–Phong.

Геометрия додекаэдра остаётся первой геометрией в индексном буфере, поэтому её `index_count` по-прежнему отделён от диапазонов сфер и цилиндров, используемых только для визуализаторов света.

## Сборка в Windows / Visual Studio

Нужны Visual Studio с C++ workload, CMake, Vulkan SDK и `glslc` из Vulkan SDK. Из корня проекта выполните конфигурацию:

```powershell
cmake -S . -B build-debug -G "Visual Studio 18 2026" `
  -DFETCHCONTENT_SOURCE_DIR_GLFW="C:/путь/к/проекту/Lab1CG/build-debug/_deps/glfw-src" `
  -DFETCHCONTENT_SOURCE_DIR_VK-BOOTSTRAP="C:/путь/к/проекту/Lab1CG/build-debug/_deps/vk-bootstrap-src" `
  -DFETCHCONTENT_SOURCE_DIR_VULKANMEMORYALLOCATOR="C:/путь/к/проекту/Lab1CG/build-debug/_deps/VulkanMemoryAllocator-src" `
  -DFETCHCONTENT_SOURCE_DIR_IMGUI="C:/путь/к/проекту/Lab1CG/build-debug/_deps/imgui-src"
```

Замените `C:/путь/к/проекту/Lab1CG` на путь к своему исходному проекту, в котором уже находятся эти зависимости. Если исходники библиотек не нужно переиспользовать, удалите все четыре параметра `FETCHCONTENT_SOURCE_DIR_...` — тогда CMake попробует скачать зависимости через Git.

Сборка:

```powershell
cmake --build build-debug --config Debug --parallel
```

Запускайте исполняемый файл из корня проекта, чтобы относительные пути к шейдерам работали:

```powershell
.\build-debug\Debug\vulkan-starter-app.exe
```

CMake пересобирает SPIR-V из исходных шейдеров. Не используйте старые `.spv` от первой лабораторной, поскольку в новой версии добавились атрибут нормали и другие descriptor bindings.

## Примечание по проверке

Исходники собраны в архив и проверены на согласованность имён полей и интерфейсов. Полную сборку под Windows/Vulkan SDK в этой среде выполнить нельзя, поэтому после распаковки нужно собрать проект на своей машине и проверить сообщения компилятора и Vulkan validation layer.
